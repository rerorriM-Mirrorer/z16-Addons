# Agent entry point

Before changing this repository or preparing a testing package, read the current root-level `WORKFLOW.md` and `TESTING.md` when present. Re-read them when resuming work; do not rely on remembered or copied versions.

If either file is absent, consult the [canonical NPCMirror WORKFLOW.md](https://github.com/rerorriM-Mirrorer/ffxi-NPCmirror/blob/main/WORKFLOW.md) and the repository's existing README, development notes, branches, and verifiable testing history. Establish missing project guides when preparing a new substantive development or testing batch; do not invent historical results.

`WORKFLOW.md` contains Agathos, Design, and development practices. `TESTING.md` contains project-specific tests, cumulative history, user feedback, and unresolved questions. Follow these conventions while preserving existing project-specific guidance and known-good behavior.

During substantial work, provide frequent concise progress and intention updates. Make small, coherent, traceable commits. Before delivery, perform available checks, distinguish static or simulated verification from live FFXI testing, update testing records without silently removing history, and report commit/push status and pending tests.

In testing ZIPs, include `WORKFLOW.md` and `TESTING.md` alongside the delivered addon or patch files (inside the addon folder when present), not as extra copies at the outer ZIP root.
